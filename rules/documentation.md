# 文档与文件约定

## 文档约定

- 简洁
- 减少不必要的负面表述
- 删除文档内容时，同时清理围绕它形成的失效描述、引用、占位和纯历史性提示。不要在当前状态文档中留下历史墓碑。


## 认可署名

AI 仅在主动认可内容时署名。human 署名仅在 human 明确提出，或明确同意以 human 身份签名时由 AI 代为写入；不得从一般性的同意、继续执行、未反对或对其他修改的认可中推断 human 认可。未署名不代表认可或反对；撰写、整理和保存内容也不自动构成认可。

- **格式**：AI 使用 Markdown HTML 注释 `<!-- 认可：平台 [模型] [模式] -->`；human 使用 `<!-- 认可：human -->`。指定范围格式同理，例如 `<!-- 认可范围：本节；认可：human -->`。AI 平台必填，模型和模式仅在能够可靠确认时填写，不猜测。多个身份可使用 `；` 分隔。
- **含义**：human 署名表示 human 明确认可指定内容，由 AI 按其明确指令或授权代为记录；不表示原创、已获证明或超出指定范围的认可。AI 署名表示该 AI 独立认可指定内容，不表示原创或已获证明；不得代其他 AI 署名，也不得继承其他 AI 的认可。同一范围内相同身份不重复署名。
- **范围**：默认认可注释之前的上一非空文本块（以空行分隔）；也可指定 `<!-- 认可范围：本节；认可：ChatGPT GPT-6 -->` 或将 `本节` 换成 `全文`。本节指最近的 Markdown 标题至下一同级或更高级标题前。
- **版本与失效**：GitHub Actions 自动将新增认可绑定到具体 Git 提交和内容指纹，归档为 `endorsements/v1/` 下的附注 Tag。认可范围内任何文字变化均使原署名失效，包括润色与标点；自动移除失效署名。历史版本由 Git Tag 保存，当前文档不保留失效说明。
- **注意**：自动处理在推送到 `main` 后运行；工作流未成功完成前，不应将尚未验证的署名视为有效。

## 文件职责

- `README.md`：说明工作台的定位，提供项目入口。
- `AGENTS.md`：Agent 的最小启动与导航协议，说明项目结构、任务入口及适用规则；不重复规则正文。
- `docs/`：保存可跨对话复用的研究知识、当前有效观点与决策、稳定结论及必要依据。只维护当前有效状态，不保存完整讨论、任务过程或聊天记录。
- `rules/`：定义工作台参与者（包括 Agent）需要遵守的约定，说明协作与工作的边界；主要由人类审视和调整，按任务读取相关规则。
- `rules/workflows/`：研究、日常整理等具体工作流程，说明如何开展相应工作。
- `rules/code-maintenance.md`：代码变更与维护约定；代码应在对应代码仓库中操作。
- Draft 文件与目录：用于暂存和隔离尚未成为正式内容的材料，不具有正式规则效力；遵守 [Draft 隔离](drafts.md)。
