# Clock（Draft）

> 本文集中记录当前关于 Clock / 时间机制的讨论。它是待讨论的研究议题，不是已确定的模块设计或实现方案。

## 当前定位

- Clock 可以后置讨论。当前更适合先推进动机、激素与情绪、自唤醒、记忆等议题；待这些机制暴露出具体的时间需求后，再判断 Clock 应承担什么作用。
- 这是研究讨论顺序的安排，不代表时间对 Agent 不重要，也不排斥实验和运行时使用基础计时能力。
- 当前产品方向曾将时间机制列为 Agent 持续认知的一部分；这只是宽泛的方向表述，不意味着已经决定把 Clock 设计成独立的核心认知模块，也不意味着其职责和优先级已经确定。

## 需要区分的概念

### 时间基础设施

当前时间来源、时间戳、计时器、定时触发和任务调度等，属于实验或运行时可能使用的基础设施。使用这些能力不等于已经提出了认知层面的 Clock 机制。

### 认知层面的时间机制

这里的 Clock 指时间信息或时间相关变化是否、以及如何参与 Agent 的内部状态、认知和行为。目前尚未确定它是否需要独立机制、内部表示或专门模块。

### 自唤醒与定时唤醒

自唤醒关注 Agent 是否主动发起认知活动；定时唤醒是由计时或调度设施触发活动。定时触发可以提供活动机会，但本身不等于动机，也不等于 Agent 自主发起活动。

## 与相邻议题的边界

此前讨论过外界输入与自唤醒之间的相对关系可能与类似孤独感的现象有关。比值在这里是研究者观察现象的一种视角，不意味着 Agent 需要显式计算它、维护两个计数器，或因此引入一个 Clock 内部变量。这个观察更接近自唤醒与情绪议题，不预先归入 Clock 的设计。

同样，不应因为其他机制具有时间上的变化或发生顺序，就预先要求它们依赖一个完整的 Clock 模块。

## 后续讨论时再回答的问题

- 其他机制实际需要哪类时间信息：先后顺序、经过时长、间隔、周期，还是截止时间？
- 这些需求能否由普通时间基础设施满足，还是确实需要影响认知的内部机制？
- 如果时间信息参与内部状态，它具体改变了什么认知或行为？
- 如何通过对照和运行观察，区分时间机制本身的贡献与动机、情绪、记忆等其他机制的贡献？

在出现具体研究需求前，不预设统一的时间模型、内部变量、公式或模块边界。
