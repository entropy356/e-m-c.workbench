# 决策与观点清单

本清单记录当前有效的研究背景与指导观点，供项目讨论、实现和接手时参考。

- **背景**说明研究动机与方向，不代表技术方案已经确定。
- **观点**记录当前采用的原则与取向；涉及模型效果的判断仍需数学分析和实验检验。
- 仅维护当前有效的内容，历史变化由 Git 保存。

### 背景

#### G-B1｜Agent 的最终愿景

希望探索一种 Agent：即使完全了解其构造、运行机制和内部信息，仍然认为它值得被作为独立个体对待。

### 观点

#### G1｜最小化历史

以 Git 作为历史兜底，当前文档只维护当前有效的状态及其必要依据。

**文档**：删除或改变当前设计时，应同步清理文档中的失效描述、引用、占位和纯历史性提示，不留下「已删除 XX」等历史墓碑。当前设计仍然需要的约束、取舍和依据可以保留，不因其涉及未采用的方案而视为历史内容。

**代码**：遵循[代码维护约定](../rules/code-maintenance.md)。


#### G3｜接手者友好

项目的当前状态应当能够被独立理解。

接手者不应需要追溯 Git 历史、旧文档或聊天记录才能理解项目结构、运行方式与有效设计。

理想情况下，Agent 应主动关注自身持续运行所依赖的条件与资源，并表现出维持运行的倾向。

#### G8｜Agent 的动机

Agent 的“动机”本身很重要，是理解和设计 Agent 时需要关注的因素。

## 二、e-m-c 项目

### 背景

#### E-B1｜研究定位

e-m-c 研究并尝试开发一类有情绪、记忆和自唤醒的 Agent。

<!-- 认可范围：本节；认可：human -->

#### E-B2｜以具体项目探索人机协作

e-m-c 的主线是 Agent 研究，支线是借助这一研究实践探索人与 AI 的协作方式。

这种取向来自「用以致学」的个人偏好：通过具体实践，推动更上层的方法与能力发展。协作方式本身可以是被观察和改进的对象，但不预设已有一套固定的方法论。

<!-- 认可范围：本节；认可：human -->

### 观点

#### E2｜动态调整推理参数

探索通过 Agent 的内部状态动态调整 LLM 推理参数，从而影响 Agent 的认知与行为。

<!-- 认可范围：本节；认可：human -->

#### E3｜记忆与持续认知

关注琐碎细节的长期留存，以及既往经历对 Agent 持续认知与行为的影响。

<!-- 认可范围：本节；认可：human -->

#### E4｜以 DSH Desktop Agent Preset 为主要产品形态

e-m-c 面向用户的主要目标产品形态是 DSH Desktop 中可安装、独立选择的 **Agent Preset（Agent 模式）**。情绪、记忆与时间机制参与 Agent 的持续认知；产品实现优先复用 DSH 的运行、会话管理、模型调用、工具执行与桌面交互能力。

研究使用独立的 `e-m-c.runtime` 和云端实验环境，注重灵活性、轻量与低依赖。认知模型及实验实现自主演化，按需与 DSH 对接。

DSH Agent Preset 可通过 Cordis 插件组合实现，具体方案由工程验证确定。

技术参考：[Agent Preset](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/preset/agent-preset/README.md)、[DSH 架构](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md)。
